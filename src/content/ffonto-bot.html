FFOnto-Bot is a chat assistant that answers questions in plain English from the FFOnto knowledge graph. It runs entirely on local models, and every answer shows the query and the facts it was based on.

GitHub

The source code is at {{bot_repo_url}}. The repository contains:

  • the ontology modules;
  • the lifting scripts and the derivation rules;
  • the 27 competency-question queries and their tests;
  • the GraphDB loader;
  • the assistant itself: the FastAPI service, the Streamlit chat interface, an optional MCP server and the evaluation scripts.

How to Use

FFOnto-Bot needs GraphDB with the FFOnto repository loaded, and Ollama for the local language models. A GPU with 16 GB of memory runs the default 14-billion-parameter model comfortably.

  1. Get the models. 
    ollama pull qwen2.5:14b      # routing and answers
ollama pull bge-m3           # embeddings for search
ollama pull qwen2.5vl:7b     # optional: reads figures in documents
  2. Install and index. 
    pip install -r qa/requirements-qa.txt
python graphdb/load_graphdb.py        # load ontology, data and rules into GraphDB
python -m qa.build_index              # example questions and documents
  3. Start the service and the chat. 
    uvicorn qa.api:app --port 8000
streamlit run qa/ui_streamlit.py      # opens http://localhost:8501
  4. Ask. Choose an image or audio record in the sidebar, then ask about it, for example Are the firefighters wearing gloves?, Is the smoke score above the threshold? or What hazards are present?. Questions about weather need a site and date, such as What was the FWI at Bejaia on 2012-06-07?. Open Evidence under an answer to see the query and rows.

Capabilities

Answers from the graph, not from memory
For questions about data, the language model only chooses which tested competency-question query to run. The answer is written from the returned rows alone. If the graph has no evidence, the bot says so instead of guessing.
Questions outside the 27 patterns
When no competency question fits, the bot writes its own SPARQL from the ontology schema. The query is checked first: read-only, a row limit enforced, and only ontology terms used. It runs only if it passes.
General wildfire knowledge
Definitions and advice come from your own documents and the ontology's background knowledge, with citations. Charts, maps and tables inside PDFs are searchable too, and the figures an answer relies on are shown with it.
Visual answers
Results such as model scores against thresholds, FWI trends or weather against danger thresholds come with a chart drawn from the same rows.
Traceable evidence
Every reply carries its route, the competency question, the SPARQL query, the result rows and the sources.
Private by design
All models run locally through Ollama, so no data or question leaves the machine.
Tool access for other agents
An optional MCP server exposes the knowledge graph as tools: list and run competency questions, run SPARQL, look up ontology terms and search documents.

Intended Users

  • Fire and emergency analysts who need a quick, explainable summary of what the images, audio and weather say about an incident, including where they disagree.
  • Researchers in knowledge graphs, multimodal learning and disaster informatics who want a tested benchmark for ontology-grounded question answering.
  • Data and model developers who want to inspect model outputs, thresholds and provenance across a dataset.
  • Educators and students learning about fire weather, firefighter safety and semantic technologies.

FFOnto-Bot supports decisions and does not replace them. Model outputs can be wrong, the danger thresholds in version {{version}} are placeholders, and operational decisions remain with qualified personnel.
