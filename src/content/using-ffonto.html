FFOnto data is queried with SPARQL. This chapter shows where to send queries and gives tested examples you can adapt.

How to Query FFOnto

A query needs the ontology, the vocabulary and the data in one place. There are three common ways to get that.

In GraphDB

Load the repository with the provided loader, then open the GraphDB Workbench at http://localhost:7200, choose the ffonto repository and use the SPARQL editor. Each source is in its own named graph, so you can query everything or restrict a query to one modality:

SELECT ?g (COUNT(*) AS ?triples)
WHERE { GRAPH ?g { ?s ?p ?o } }
GROUP BY ?g
ORDER BY ?g
# , …/audio, …/weather, …/scene, …/inferred, …/ontology, …/vocab

Programs can use the same repository as a SPARQL endpoint:

curl -s http://localhost:7200/repositories/ffonto \
  -H "Accept: text/csv" \
  --data-urlencode "query=PREFIX ffo:  SELECT (COUNT(?r) AS ?records) WHERE { ?r a ffo:DataRecord }"

In Python

For small graphs, rdflib is enough. Load the ontology modules and the lifted data, then query:

from rdflib import Graph

g = Graph()
for f in ["ontology/ffonto-core.ttl", "ontology/ffonto-vocab.ttl",
          "ontology/danger-rules.ttl", "data/kg_inferred.ttl"]:
    g.parse(f, format="turtle")

for row in g.query(open("queries/CQ05.rq").read()):
    print(row.record, row["class"], row.confidence, row.threshold)

data/kg_inferred.ttl already contains the facts derived by the rules. If you load the raw data/kg.ttl instead, run python scripts/run_cqs.py first, which applies the rules.

Things to know

  • Kinds are concepts. Ask for ?e ffo:hasKind ffv:Firefighter, not for a class ffo:Firefighter. To include narrower kinds, follow the hierarchy: ?e ffo:hasKind/skos:broader* ffv:Person.
  • Scores are observations. A confidence belongs to an ffo:ModelObservation attached to the record with ffo:hasObservation, never to the record directly.
  • Use labels for display. Every concept has an English skos:prefLabel.
  • Derived facts live in the inferred graph. ffo:detectedClass, ffo:hasCondition, ffo:ModalityConflict and ffo:Hazard exist only after the rules have run.

SPARQL Examples

Each example is one of the tested competency-question queries, shortened to its core. The prefixes are the same in every example:

PREFIX ffo:  
PREFIX ffv:  
PREFIX skos: 
PREFIX sosa: 
PREFIX prov: 
PREFIX rdfs:

Is each score above its threshold? (CQ05)

SELECT ?record ?class ?confidence ?threshold ?aboveThreshold
WHERE {
  ?record ffo:hasObservation ?o .
  ?o ffo:predictedClass ?class ;
     ffo:confidence ?confidence ;
     ffo:usedThreshold/ffo:thresholdValue ?threshold .
  OPTIONAL { ?o ffo:aboveThreshold ?aboveThreshold }
}
ORDER BY ?record ?class

On the example image from Data Sources, this returns fire 0.16, threshold 0.55, false and smoke 0.73, threshold 0.60, true.

Which required PPE is missing? (CQ17)

SELECT ?person ?kind ?missing
WHERE {
  ?sd ffo:describesRecord ?record ; ffo:depicts ?person .
  ?person ffo:hasKind ?k .
  ?k skos:broader* ffv:Person ; skos:prefLabel ?kind .
  ?k ffo:requiredPPE ?req .
  FILTER NOT EXISTS { ?person ffo:wears ?req }
  ?req skos:prefLabel ?missing .
}

The required equipment is background knowledge in the vocabulary (for example, a firefighter requires a helmet, fire-resistant clothing, gloves and eye protection). The query compares it with what the vision model saw.

How is the FWI trending at a site? (CQ09)

SELECT ?site ?date ?FWI ?previousFWI ?fwiTrend
WHERE {
  ?w a ffo:WeatherRecord ;
     ffo:atSite/ffo:siteName ?site ;
     ffo:observationDate ?date ;
     ffo:fwi ?FWI .
  OPTIONAL { ?w ffo:previousRecord/ffo:fwi ?previousFWI }     # link derived by rule R08
  BIND(IF(!BOUND(?previousFWI), "n/a",
       IF(?FWI > ?previousFWI, "increasing",
       IF(?FWI < ?previousFWI, "decreasing", "stable"))) AS ?fwiTrend)
}
ORDER BY ?site ?date

Which hazards exist, and what should be done? (CQ24 and CQ25)

SELECT ?eventCode ?hazardType ?reason ?action
WHERE {
  ?h a ffo:Hazard ; ffo:hasHazardType ?ht .
  ?ht skos:prefLabel ?hazardType .
  OPTIONAL { ?h ffo:inEvent/ffo:eventCode ?eventCode }
  OPTIONAL { ?h rdfs:comment ?reason }
  OPTIONAL { ?ht ffo:mitigatedBy/skos:prefLabel ?action }
}
ORDER BY ?eventCode ?hazardType

Browse the vocabulary: every kind of hand tool

SELECT ?tool ?label
WHERE {
  ?tool skos:broader+ ffv:HandTool ;
        skos:prefLabel ?label .
}
ORDER BY ?label
