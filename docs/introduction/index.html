Chapter 1

Introduction

FFOnto is an ontology for forest-fire situational awareness. It turns drone images, field audio and fire-weather records into one knowledge graph that people and software can question, with every answer traceable to the record and the model it came from.

What is FFOnto?

During a wildfire, evidence arrives in different forms. A drone frame shows smoke over a ridge, a microphone picks up a crackle or an explosion, and the weather station reports low humidity and a rising Fire Weather Index (FWI). Machine-learning models turn each of these into labels, captions and scores, but those outputs live in separate files, use different vocabularies and often disagree with each other.

The Forest Fire Ontology (FFOnto) gives these sources one shared meaning. It defines what a fire event, a data record, a scene entity and a model observation are, and how they relate. Data described with FFOnto becomes a knowledge graph: a network of facts that can be queried with SPARQL, checked for consistency, and extended by rules that derive conditions, conflicts and hazards.

Three ideas shape the ontology:

  • World, data and claims are kept apart. When a classifier says smoke, 0.73, FFOnto records that as a claim about an image, with its confidence, threshold and model, not as a fact about the fire. Conflicting claims can then sit side by side and be compared.
  • Fine-grained kinds are a vocabulary, not a class hierarchy. Helmets, Pulaskis, crown fires and scorched trees are SKOS concepts. A new tool or hazard is one new concept, and the schema does not change.
  • Knowledge that can be computed is derived by rules. Danger conditions, cross-modal conflicts and hazards are produced by SPARQL rules from the stored observations, so changing a threshold never means editing data.

Version 2, described in this book, was rebuilt from scratch around competency questions: the questions the knowledge graph must be able to answer, taken from the ForestFire-VQA dataset.

Resources

ResourceWhat it contains
Ontology documentation Every class, property and concept with its definition (generated with WIDOCO), plus a WebVOWL diagram.
Controlled vocabulary 374 SKOS concepts in 15 schemes, browsable as a hierarchy.
ffonto-core.ttl, ffonto-vocab.ttl, danger-rules.ttl The three ontology modules in Turtle.
ffonto-shapes.ttl SHACL shapes that check data quality (missing metadata, alert readiness, missing PPE).
ffonto.context.jsonld JSON-LD context that maps the raw image JSON, audio JSON and weather CSV fields to ontology terms.
ForestFire-VQA dataset Images, audio and question–answer pairs from which the competency questions were derived.
FFOnto-Bot source code The question-answering assistant described in FFOnto-Bot.

PREFIX ffd:  <http://purl.org/ffonto/data/>     # instance data
